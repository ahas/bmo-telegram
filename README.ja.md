# telegram

Telegram のチャットプロバイダー `bmo-telegram` です。ベースライブラリ `bmo-chat` のチャットプロトコルを通じて、
チャットレシーバーに対して Telegram として振る舞います。対応する読み取りモード、できること、ルームが読む方言
(dialect)を宣言し、ボットアカウントでルームを読み、12 種類の送信動詞を送り、ルームでの発言をレシーバーに渡します。
ボットでは見えないものや取得できないもの、そしてオーナー自身の発言は、読み取り専用のオーナー本人のアカウントが
背後で担い、これは別プロセスのリーダー(reader)が保持します。

## 構成

| フォルダー | 内容 |
|---|---|
| `src/` | サービス自身のパッケージ:プロバイダー、Bot API 接続、ルート |
| `dialect/` | `telegram-dialect`、すなわち `telegram-html` 方言:Markdown から Telegram の HTML への変換、構造チェック、折りたたみ、メッセージへの分割 |
| `picture/` | `telegram-picture`、画像の読み取りと再描画:形式、透過、Telegram が写真として受け付けるアップロード、サイズ内に収めた画像 |
| `reader/` | リーダー。MTProto でオーナーのアカウントを保持する bun パッケージで、テストは `reader/tests/` にある |
| `tools/` | デプロイが配置するホステッドツール:サービス経由で一つのチャットの最近のメッセージを、オーナーの指示に限り取得する |
| `policy/` | プロバイダーの固定値と英語の文言:上限、拒否、プレースホルダー |
| `tests/` | リポジトリ全体にわたるチェックと、サービスのテスト |
| `deploy/` | デプロイがリンクする二つのサービスユニット:Rust のプロバイダーと bun のリーダー |
| `docs/` | プロバイダーの動作を定める正式なドキュメント |

ルートには、サービスのパッケージを兼ねる Cargo ワークスペースのマニフェスト、`VERSION` に記されたバージョン、
`testbed.toml`(このリポジトリをどうテスト・チェック・ビルド・デプロイするかを記したテストベッドの宣言)、
`install.toml`(新しいマシンへのインストールに必要なものの宣言で、`bmo install` が読みます)、`rustfmt.toml`、`CLAUDE.md` があります。

## ドキュメント

| ドキュメント | 内容 |
|---|---|
| `docs/api.md` | プロバイダーの固定された公開 API:チャットプロトコルのルート、ワイヤー形式、ページ。同じ契約を機械可読な形にした `docs/openapi.json` |
| `docs/boundary-api.md` | 境界:提供するルート、レシーバーへの呼び出し、サービスとリーダーの接点、設定 |
| `docs/telegram.md` | プロバイダー:宣言、ルームの読み方、各送信の動作、オーナーの声、`telegram-html` 方言 |
| `docs/reader.md` | リーダー:オーナーのアカウント、接続、履歴の走査、プロフィール画像、そして TypeScript である理由 |
| `docs/tools.md` | ホステッドツール:エントリー、引数、オーナーの指示、プロバイダーへの到達先 |
| `docs/checks.md` | リポジトリのチェック:依存関係、マニフェスト、構成、バージョン、ハングル、個人データ、名前 |
| `docs/PERSONAL-DATA.md` | リポジトリの個人データ禁止規則:追跡対象のファイルに含めてはならないもの、その代わりに置くもの、それを守るチェック |

## バージョン

- **リポジトリ全体で一つのバージョン、** つまりワークスペースのバージョンを使います。`VERSION` がそれを保持し、
  ワークスペースのバージョンはそれと等しく、リーダーの `package.json` も同じバージョンを持ちます。
- **バージョンはオーナーが宣言したリリースでのみ動きます。** 規則は bmo-chat の `docs/conventions.md`
  「Versions」にあります。コミット、デプロイ、修正、契約の変更ではバージョンは動かず、デプロイはコミットで
  区別します。

## ビルドとテスト

Cargo はテストベッドの Cargo 動詞を通じて実行し、共有の一つのビルドディレクトリでビルドします。インストール済みの
テストベッドに Cargo 動詞がない場合は、`bmo cargo` が同じ動詞を提供します。

```sh
bmo cargo check --workspace --all-targets
bmo cargo test --workspace
bmo cargo clippy --workspace --all-targets -- -D warnings
bmo cargo fmt --all --check
```

リーダーのテストは `reader/` で実行します。

```sh
bun install
bun test
```
